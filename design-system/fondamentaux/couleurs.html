Couleurs

Palette DSFR : tokens sémantiques (light/dark) à utiliser dans les maquettes, et palette de référence sous-jacente. Source : Figma « DSFR - v1.15.0 - Fondamentaux » (page Couleurs) — même nomenclature que les variables CSS officielles du DSFR (--text-default-grey, --background-action-high-blue-france, etc.).

🔗 Documentation officielle DSFR : Couleurs
À utiliser dans les maquettes : toujours les tokens sémantiques (« Decisions ») ci-dessous — jamais une couleur de la palette brute directement. Un token donné change de valeur hexadécimale entre thème clair et thème sombre ; c'est voulu, c'est lui qui porte le sens (ex. --text-disabled-grey), pas la couleur.

Tokens spécifiques JeVeuxAider (pas DSFR officiel)

Certains fonds/couleurs utilisés en vrai sur le produit ne correspondent à aucun token « Decisions » de dsfr.min.css : c'est un choix produit posé par-dessus la base DSFR, jamais nommé nulle part (ni en code, ni en Figma) — juste recopié en hex à chaque usage. Documentés ici au fur et à mesure qu'on les découvre, pas un audit exhaustif.

Token JVALightDarkUsage réel
--background-warm-neutral#F9F6F2#211D19Couleur de fond de base du site (confirmé par l'équipe produit). S'appuie sur la valeur brute DSFR --beige-gris-galet-975-75 (qui a un vrai pendant dark), défini dans design-system/patches.css — c'est aussi, sans lien exprès, la couleur déjà utilisée par .demo dans _layouts/default.html. À ne pas confondre avec --beige-gris-galet-950-100 (#F3EDE5), un ton plus saturé utilisé en fond de section sur certaines pages (pages/reseaux/[slug].vue, pages/organisations/[slug].vue...) — un usage différent, pas encore tokenisé.

Côté Figma : créé comme styles (pas variables — DSFR lui-même utilise des styles, pas des variables, dans ce fichier ; un jeu Light//Dark/ par style plutôt qu'un mode qui bascule) dans « Composants JVA » : Light/JVA/Fond neutre chaud et Dark/JVA/Fond neutre chaud. Un style ne peut pas référencer la valeur brute DSFR comme le fait var(--background-warm-neutral) en CSS — si beige-gris-galet-975-75 change un jour côté DSFR, ces deux styles devront être resynchronisés à la main.

Cohérence avec le code

Confirmé : --text-disabled-grey vaut #929292 en light dans Figma, ce qui correspond à ce qu'on a tranché pour DsfrButton (le code utilisait #656565 par endroits — voir À homogénéiser).

Écart : la palette jva-blue définie dans tailwind.config.ts reprend certaines valeurs DSFR (500: #000091 = blue-france-sun-113, 800/900 = ses états hover/active) mais avec sa propre numérotation Tailwind (50–900), différente de l'échelle DSFR (75–975 + sun/main). Pas un bug, mais à garder en tête : le nom de la classe Tailwind ne renseigne pas sur le token DSFR sémantique correspondant.
