Écran — Vérification du code de connexion (OTP)

Redesign de l'étape « code reçu par e-mail » du flux de connexion, avec les composants déjà cataloguée dans ce design-system. Basé sur le code réel de la branche feature/otp (composants SplitLayout, EmailOtpForm, OtpInput), pas encore en production.

Cet écran introduit aussi un nouveau gabarit de mise en page pas encore documenté ici : SplitLayout, utilisé sur les pages d'authentification (connexion, mot de passe oublié, inscription). Ce n'est pas encore un composant du catalogue des 164 — je le documente à partir du code réel de la branche.

Ce que je changerais par rapport à l'implémentation actuelle

ConstatProposition
Le message d'erreur utilise text-red-600 (rouge Tailwind générique), différent du rouge DSFR officiel #CE0500 + icône utilisé partout ailleurs dans l'app (ex. BaseFormError).Réutiliser le pattern BaseFormError tel quel — même composant, cohérence visuelle immédiate.
Les 6 cases du code n'ont pas de label individuel : seul le champ caché d'autofill porte un sr-only « Code de connexion ». Un lecteur d'écran annonce 6 champs identiques sans distinction.Ajouter un aria-label par case (« Chiffre 1 sur 6 », etc.) — aucun changement visuel, gain d'accessibilité direct.
Le lien « Renvoyer le code » reste cliquable sans limite. Un mécanisme proche (l'OTP de réactivation de compte archivé) a déjà nécessité un correctif anti-bruteforce par le passé.Décompte visible de 30 s pendant lequel le lien devient un texte désactivé — protège à la fois contre le double-clic frustrant et le spam de codes.
